# План переделок

План составлен по результатам аудита `v2.4`. Приоритет — сначала криптографическая
корректность, затем точность измерений, надёжность и сопровождаемость.

## Этап 1. Криптографическая корректность — выполнено в v2.5

- [x] Передавать `CKM_GOST28147` случайный IV длиной 8 байт.
- [x] Передавать совместным механизмам ГОСТ-подписи обязательный OID алгоритма
      хеширования и не использовать отсутствие параметров как недокументированный
      переключатель software/hardware.
- [x] Использовать для `CTR_ACPKM` ненулевой период смены ключа и уникальную
      синхропосылку для каждой операции.
- [x] После измерения расшифровывать последний шифротекст и сравнивать его с
      исходными данными.
- [x] После измерения проверять последнюю подпись.

## Этап 2. Точность benchmark — выполнено в v2.6

- [x] Полностью вынести подготовку буферов и параметров из измеряемых участков.
- [x] Добавить отдельные показатели setup, PKCS#11 operation, total и throughput
      в MiB/s.
- [x] Добавить настраиваемый прогрев перед измерением.
- [x] Зафиксировать, входит ли генерация ключа и параметров механизма в каждый
      вид измерения.

## Этап 3. Надёжность — выполнено в v2.7

- [x] Сопоставлять ключевые пары по исходным байтам `CKA_ID`, не по строке для
      отображения, и корректно обрабатывать дубликаты.
- [x] Не позволять ошибкам очистки скрывать исходную ошибку операции.
- [x] Корректно учитывать владение `C_Initialize/C_Finalize`.
- [x] Обрабатывать ошибки загрузки PKCS#11-библиотеки без traceback.
- [x] Предлагать выбор слота, если подключено несколько токенов.
- [x] Сохранить запланированную подстановку демонстрационного PIN `12345678`,
      но явно показывать значение по умолчанию в приглашении.
- [x] Исключить или обнаруживать оставшиеся после аварии временные token objects.

## Этап 4. Чистота кода — выполнено в v2.8

- [x] Одним компактным рефакторингом удалить мёртвый код, сделать описания
      алгоритмов и шаблоны ключей декларативными, убрать лишнее дублирование и
      жёстко заданные даты, не меняя поведения приложения и сохранив один `app.py`.

## Этап 5. Сборка и выпуск

- [x] Добавить базовые unit-тесты параметров `CTR_ACPKM`, IV ГОСТ 28147-89 и
      OID совместного механизма подписи.
- [ ] Обновить GitHub Actions до актуальных версий и закрепить версию

- [ ] Добавить лицензию, короткий changelog и релизный тег.
